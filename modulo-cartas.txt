║  1. BASE DE DATOS                                                          ║
╚══════════════════════════════════════════════════════════════════════════════╝

Schema: public
Tabla:  letters

  1.1  Columnas

  ┌──────────────────┬──────────────────────────┬──────────┬──────────┐
  │ Columna          │ Tipo                     │ Nulo     │ Default  │
  ├──────────────────┼──────────────────────────┼──────────┼──────────┤
  │ id               │ uuid                     │ NOT NULL │ gen_uuid │
  │ from_name        │ text                     │ NOT NULL │ —        │
  │ to_name          │ text                     │ NOT NULL │ —        │
  │ subject          │ text                     │ NOT NULL │ —        │
  │ body             │ text                     │ NOT NULL │ —        │
  │ unread           │ boolean                  │ nullable │ null     │
  │ created_at       │ timestamptz              │ nullable │ null     │
  └──────────────────┴──────────────────────────┴──────────┴──────────┘

  id          → UUID autogenerado (gen_random_uuid()).
  from_name   → Nombre del remitente (texto libre, NO foreign key).
  to_name     → Nombre del destinatario (texto libre, NO foreign key).
  subject     → Asunto de la carta.
  body        → Cuerpo de la carta (texto plano, saltos de línea = párrafos).
  unread      → true = no leída, false/null = leída.
  created_at  → Fecha de creación en UTC.

  1.2  Constraints

  ┌──────────────────────────┬──────────────┬──────────────┐
  │ Tipo                     │ Columna      │ Referencia   │
  ├──────────────────────────┼──────────────┼──────────────┤
  │ PRIMARY KEY              │ id           │ —            │
  └──────────────────────────┴──────────────┴──────────────┘

  No hay foreign keys ni unique constraints (pueden existir cartas con
  mismo asunto/de/para). Sin índices adicionales.

  1.3  RLS (Row Level Security)

  NO hay políticas RLS definidas para esta tabla. La tabla está abierta
  a cualquier usuario autenticado (el middleware de la app protege las
  rutas, pero la tabla en sí no tiene restricciones a nivel DB).


╔══════════════════════════════════════════════════════════════════════════════╗
║  2. BACKEND — SERVER ACTIONS (modules/cartas/actions.ts)                  ║
╚══════════════════════════════════════════════════════════════════════════════╝

  Archivo:   modules/cartas/actions.ts
  Directiva: 'use server' — se ejecutan en el servidor, nunca en el cliente.
  Cliente:   createClient() desde lib/supabase/server.ts (cookie-based).

  2.1  getLetters()

  ┌────────────┬────────────────────────────────────────────────────────┐
  │ Firma      │ getLetters(): Promise<Letter[]>                       │
  │ Query      │ SELECT * FROM letters ORDER BY created_at DESC        │
  │ Retorno    │ Arreglo de Letter (vacío si no hay datos o error)     │
  │ Error      │ Silent — no lanza error, retorna [] si falla query    │
  │ Llamada    │ desde CartasPage (server component) → CartasApp       │
  └────────────┴────────────────────────────────────────────────────────┘

  2.2  insertLetter()

  ┌────────────┬────────────────────────────────────────────────────────┐
  │ Firma      │ insertLetter(from_name, to_name, subject, body)       │
  │            │   → Promise<{ success, error?, letter? }>             │
  │ Insert     │ INSERT con unread = true, retorna el registro creado  │
  │ Validación │ Ninguna server-side (solo NN de columna en DB)        │
  │ Revalidate │ revalidatePath('/cartas')                             │
  │ Errores    │ Retorna { success: false, error: mensaje } si falla   │
  └────────────┴────────────────────────────────────────────────────────┘

  2.3  updateLetter()

  ┌────────────┬────────────────────────────────────────────────────────┐
  │ Firma      │ updateLetter(id, subject, body)                       │
  │            │   → Promise<{ success, error?, letter? }>             │
  │ Update     │ UPDATE subject, body WHERE id = ?                     │
  │ Revalidate │ revalidatePath('/cartas')                             │
  │ Nota       │ No actualiza from_name, to_name ni created_at         │
  └────────────┴────────────────────────────────────────────────────────┘

  2.4  deleteLetter()

  ┌────────────┬────────────────────────────────────────────────────────┐
  │ Firma      │ deleteLetter(id): Promise<{ success, error? }>        │
  │ Delete     │ DELETE FROM letters WHERE id = ?                      │
  │ Revalidate │ revalidatePath('/cartas')                             │
  └────────────┴────────────────────────────────────────────────────────┘

  3.1  CartasApp (modules/cartas/components/CartasApp.tsx)

  Propósito:    Página principal del módulo — lista de cartas + acciones.
  Tipo:         'use client' (maneja estado local + modales).
  Props:
    ┌──────────────┬──────────┬────────────────────────────────────────┐
    │ Prop         │ Tipo     │ Descripción                           │
    ├──────────────┼──────────┼────────────────────────────────────────┤

    └──────────────┴──────────┴────────────────────────────────────────┘

  Estado local:
    letters         → Letter[] — copia mutable de initialLetters.
    selectedLetter  → Letter | null — carta seleccionada para leer.
    showWriteModal  → boolean — controla visibilidad del modal de escritura.
    editingLetter   → Letter | null — carta en edición (null = nueva carta).

  Handlers:
    handleSaved(letter?)  → cierra modal, actualiza lista local + router.refresh().
    handleEdit(letter)    → abre WriteLetterModal en modo edición.
    handleDelete(id)      → elimina optimistamente de la lista local, luego
                            llama deleteLetter() y refresca.

  Render:
    ┌──────────────────────────────────────────────────────────────────┐
    │ page-header                                                      │
    │   subtitle "palabras del corazón"                                │
    │   title "Cartas"                                                 │

    │                                                                  │
    │ [if letters.length === 0]                                        │
    │   EmptyState (icono 💌, "Todavía no hay cartas")                 │
    │                                                                  │
    │ [else]                                                           │
    │   gallery-grid                                                   │
    │     letter-card × N                                              │
    │       .li-from      → from_name                                  │
    │       .li-subject   → subject                                    │
    │       .li-preview   → body truncado a 100 chars + "…"           │
    │       .li-date      → created_at formateado                      │
    │       onClick → setSelectedLetter(letter)                        │
    │                                                                  │
    │ [if selectedLetter]  → LetterReaderModal                         │
    │ [if showWriteModal]  → WriteLetterModal                          │
    └──────────────────────────────────────────────────────────────────┘

  3.3  WriteLetterModal (modules/cartas/components/WriteLetterModal.tsx)

  Propósito:    Modal para escribir o editar una carta.
  Props:
    ┌──────────────┬───────────────────────────────────────────────────┐
    │ Prop         │ Tipo                                             │
    ├──────────────┼───────────────────────────────────────────────────┤
    │ onClose      │ () => void                                       │
    │ onSaved      │ (letter?: Letter) => void                        │
    │ editLetter   │ Letter | null | undefined — null = nueva carta   │
    └──────────────┴───────────────────────────────────────────────────┘

  Estado local:
    toName    → string — default: COUPLE.name2 (Ricardo).
    subject   → string — relleno con editLetter?.subject si edición.
    body      → string — relleno con editLetter?.body si edición.
    loading   → boolean.

  Lógica:
    - Si editLetter existe → modo edición: llama updateLetter().
    - Si no → modo creación: determina from_name como la otra pareja:
        fromName = toName === COUPLE.name1 ? COUPLE.name2 : COUPLE.name1
      luego llama insertLetter().
    - Botón deshabilitado si loading o subject/body vacío.

  Render:
    ┌──────────────────────────────────────────────────────────────────┐
    │ modal-backdrop                                                   │
    │   write-modal-box                                                │
    │     modal-header → "escribir carta" / "editar carta" + ✕        │
    │     write-form                                                   │
    │       De → readonly (determinado automáticamente)                │
    │       Para → <select> con COUPLE.name1 / COUPLE.name2            │
    │       Asunto → <input>                                           │
    │       Carta → <textarea> (min-height: 280px)                     │
    │       divider                                                    │
    │       acciones → Cancelar + "✦ Enviar carta" / "✦ Guardar"      │
    └──────────────────────────────────────────────────────────────────┘

║  4. RUTA                                                                    ║
╚══════════════════════════════════════════════════════════════════════════════╝

  Archivo:  app/(app)/cartas/page.tsx
  Tipo:     Server Component (async).

  ┌──────────────┬────────────────────────────────────────────────────────┐
  │ Código       │ import { getLetters } from '@/modules/cartas/actions' │
  │              │ import { CartasApp } from '@/modules/cartas/components'│
  │              │                                                       │
  │              │ export default async function CartasPage() {          │
  │              │   const letters = await getLetters();                 │
  │              │   return (                                           │
  │              │     <div className="page active">                    │
  │              │       <CartasApp initialLetters={letters} />         │
  │              │     </div>                                            │
  │              │   );                                                  │
  │              │ }                                                     │
  ├──────────────┼────────────────────────────────────────────────────────┤
  │ Ruta         │ /cartas (dentro del grupo protegido (app)/)           │
  │ Layout padre │ app/(app)/layout.tsx (Sidebar + StarField + Toast)    │
  │ Tipo         │ Server Component — fetch inicial en servidor          │
  └──────────────┴────────────────────────────────────────────────────────┘

  Flujo:
    1. Usuario navega a /cartas
    2. CartasPage hace getLetters() (consulta Supabase desde servidor)
    3. Pasa letters como initialLetters a CartasApp (client component)
    4. CartasApp maneja el estado local y modales
    5. Mutaciones (crear/editar/eliminar) se hacen vía server actions
    6. router.refresh() sincroniza datos frescos del servidor


╔══════════════════════════════════════════════════════════════════════════════╗
║  5. TIPOS TYPESCRIPT (modules/cartas/types.ts)                            ║
╚══════════════════════════════════════════════════════════════════════════════╝

  export interface Letter {
    id: string;            // UUID
    from_name: string;     // Nombre del remitente
    to_name: string;       // Nombre del destinatario
    subject: string;       // Asunto
    body: string;          // Cuerpo (texto plano, \n = párrafos)
    unread: boolean | null; // true = no leída
    created_at: string;    // ISO 8601 timestamp
  }

  Nota: id y created_at son auto-generados por la DB al insertar.
